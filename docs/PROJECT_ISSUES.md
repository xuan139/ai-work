## 2026-10-12 — Notion catalog entry had no usable demo

- **Trigger:** A new Notion user requested a working MCP demo and a from-zero setup guide.
- **Root cause:** The catalog only listed the official remote OAuth endpoint; the portal had no Notion-specific demo or internal-integration adapter.
- **Fix:** Add an admin-only `/notion-demo` with title search, page selection, bounded LLM/tool rounds, source links, traces, missing-configuration/loading/error states, and three hard-allowlisted read tools. Preserve the official catalog entry. The optional `/mcp/notion` transport uses a separate server-side Bearer key. Hide and deny the shared adapter in ordinary employees' general MCP execution paths. No provider token is persisted in the registry or sent to a model/browser.
- **Verification:** All 216 tests passed, including 45 focused tests across Notion, MCP registry, orchestration, categories and LangChain. Tests cover pagination, nested content, truncation, unsafe IDs/arguments, denial of writes, redirect blocking, masked API errors, unauthenticated/employee access, absent credentials, search-to-read-to-answer orchestration, and success/failure auditing. JavaScript syntax and Python compilation passed. Browser checks verified the admin menu, missing-configuration state, disabled queries, sample input, Traditional Chinese/English switching, and desktop (1440px) and mobile (390px) layouts without horizontal overflow.
- **Deployment (2026-10-12):** Deployed the scoped Notion files to `/home/ubuntu/ai-work` on the existing Ubuntu server. The four changed core files matched the Git baseline before deployment; no pending processing jobs were present. Preserved `.env`, uploads and models. Backed up replaced code and SQLite using its backup API under `/home/ubuntu/backups/notion-20261012-062957`. Restarted `ai-work.service`; startup succeeded, public HTTPS `/notion-demo` returned 200, and unauthenticated `/api/notion-demo/status` returned 401. Browser verified the login-required state. All 13 Notion tests passed on Ubuntu using unittest discovery; the initial package-style test invocation could not import modules because the server lacks the complete test package. All 216 tests passed locally before deployment.
- **Not yet verified:** The user has no Notion workspace/integration yet, so real Notion API access and real LLM answer quality remain unverified. This is not a full workspace crawler, database-query engine, OAuth implementation, or proof of complete prompt-injection prevention.
- **Rollback:** Revert only the Notion-related files, imports, routes, navigation and catalog addition; disable `notion-readonly` and remove the two Notion environment variables. Existing official `notion` configuration and audit records can be retained. No existing credentials or customer records were overwritten.
- **Server rollback:** Stop `ai-work.service`, restore `code.tar.gz` from the backup above, remove only the new files listed in its `new-files.json`, then restart and check the service. Do not restore the database blindly over new customer activity; the added catalog row may remain disabled without reverting the database.

## 2026-10-10 — Enterprise evaluation baseline was not reproducible

- **Trigger:** The evaluation center had no standard employee identities or approved baseline cases, so permission and answer regression tests could not be run after deployment.
- **Root cause:** The first evaluation release provided the execution and review workflow but left test identity, department permission, source fixture, and case creation entirely manual.
- **Fix:** Add an idempotent administrator bootstrap that creates four reserved standard-employee identities, three department groups, sixteen traceable NAS source fixtures, and forty approved cases covering normal, cross-document, insufficient-evidence, cross-department, and version scenarios.
- **Verification:** Run the bootstrap twice and confirm that identity, group, source, and case counts remain stable; verify representative company, department, and private source permissions; run the targeted and full automated test suites.
- **Not yet verified:** Final-answer quality against every case depends on the configured production LLM and must be reviewed through the evaluation center after deployment. The independent judge model is intentionally not part of this phase.
- **Rollback:** Restore the pre-deployment application and SQLite backup. The seeded rows are isolated by `eval.*` usernames, `evaluation_fixture` source type, `evaluation://enterprise-baseline-v1/*` source URLs, dedicated group names, and the `enterprise-baseline-v1` suite marker.
